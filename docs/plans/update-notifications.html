NEBULA-MD · IMPLEMENTATION PLAN

Know when an update is ready.

Behavior

  • Check Chocolatey's official feed asynchronously when the primary window is shown, and every 24 hours while it remains open.
  • Compare the running application version with the latest approved stable package. Exclude prereleases and packages still in moderation, which normal upgrades cannot install.
  • Show a non-modal, dismissible banner naming the new version, with upgrade instructions and a link to the package page. Announce each newer version once per session.
  • Keep offline, timeout, and invalid-feed failures silent; retry at the next scheduled check. Cancel pending work when the window closes.

Verification

Use controlled HTTP responses and a simulated clock to test version comparisons, moderation filtering, startup and daily scheduling, cancellation, failures, and duplicate suppression. Exercise the banner in the existing WinForms smoke harness and rerun workspace checks.

Release

Commit and push the verified feature to master. Then prepare version 1.2.0, publish the executable from a pinned source commit, update its verification checksum, build and inspect the Chocolatey package, push release metadata, and submit the package.

Clarifications

None required. Notifications advise the user how to upgrade; they do not install updates automatically.
